- 如果无法全部运行 211 个样本，至少使用同一公共子集。

### 3. 增加非 LLM 基线，并明确检索收益来源

需要增加：

- 基于规则覆盖率的简单 reranking。
- 轻量级 learned reranker。
- KNN/直接光谱相似度与对比学习检索器的受控比较。

目标是回答两个问题：

- 性能提升究竟来自 LLM 推理，还是仅来自规则特征？

### 7. 系统分析并处理 MODIFY fallback 的退化

四位评审均指出：`confidence < 0.6` 时触发的 MODIFY，在所有模型上通常比 SELECT 更差。

需要：

- 在相同样本上分别报告 SELECT 与 MODIFY 的 GED、Tanimoto、validity 和触发率。
- 按错误类型、置信度区间、候选质量进行分层分析。
- 解释跨 LLM 表现不稳定的原因。
- 提出阈值、策略或结构修改约束方面的具体改进。
- 如果无法改善，应将 MODIFY 定位为负面发现或默认关闭，而不能继续将其作为已验证有效的核心能力。

### 11. 扩展失败模式分析和实践建议

重点解释：

- Gemini 的 Tanimoto 为零。
- GPT-5 parse rate 极低。
- Knowledge 的 GED 优于 Agentic，但有效分子比例下降。
- 不同 LLM 之间结果不稳定。
- parse failure、invalid SMILES 与 GED/Tanimoto 之间的关系。

应给出代表性案例、原因假设和缓解办法，并增加面向实践者的建议，例如 schema validation、retry/repair 和安全 fallback 策略。

### 12. 重写创新性定位并校准性能主张

需要明确 SpectraExpert 与以下工作的差异：

- 标准 1D ViT 检索器。
- MRKL、Toolformer、ReAct 等既有 LLM orchestration。
- MatExpert 式 Retrieval + Reasoning 框架。
- Vib2Mol、VibraCLIP、MolSpectLLM。

在仍然没有 exact match、GED/Tanimoto 增益有限且实验批次不一致的情况下，应删除或弱化“稳健识别”“决定性提升”“明显优于强基线”等表述，并在摘要、结论、表注和 limitations 中保持一致。
